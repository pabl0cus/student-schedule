# Student Schedule Community Worker for Windows

Локальний Windows-клієнт, який у дозволені користувачем години забирає з Student Schedule аудіо лекції,
транскрибує його українською через `faster-whisper` і повертає серверу JSON із таймкодами.

Це окремий підпроєкт: він не імпортує код фронтенду чи серверної частини й може бути винесений в окремий
репозиторій. У цій директорії навмисно немає вкладеного `.git`.

## Можливості

- робота у системному треї без консолі;
- Whisper `large-v3`, українська мова, VAD і послівні таймкоди;
- автоматичний вибір CUDA/`float16`, якщо CTranslate2 бачить сумісну NVIDIA GPU, інакше CPU/`int8`;
- автоматичний повтор поточної транскрипції на CPU/`int8`, якщо CUDA runtime не вдалося завантажити;
- токен лише у Windows Credential Manager через `keyring`;
- режими «Цілодобово», «Ніколи» та довільна кількість щоденних інтервалів;
- інтервали через північ, наприклад `22:00–06:00`;
- heartbeat lease, безпечне звільнення незавершеної роботи та ідемпотентне повторення готового результату;
- HTTPS для віддалених серверів; незашифрований HTTP дозволено тільки для явного loopback.

## Важлива примітка про приватність

Комп’ютер волонтера отримує нормалізовану mono 16 кГц Ogg/Opus-аудіодоріжку без відео, метаданих і розділів.
Клієнт перевіряє заявлені сервером розмір і SHA-256 навіть після відновлення часткового завантаження. Власник
такого комп’ютера технічно може зробити копію звуку, тому сервер має видавати токени лише довіреним
учасникам, а користувачів сервісу потрібно явно попереджати про community processing. Токен підтверджує право
взяти роботу, але не доводить правильність отриманої транскрипції.

## Запуск із вихідного коду

Потрібні Windows 10/11 x64 та Python 3.11 або 3.12. Інтерфейс і системний трей побудовані на PySide6,
тому Qt runtime приїжджає разом з інсталятором і не залежить від системного Tcl/Tk.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\pythonw.exe -m student_schedule_worker
```

Під час першого запуску програма попросить адресу сервера і токен адміністратора. Вона перевірить токен через
`GET /community/v1/me`, після чого збереже його у Windows Credential Manager. `config.json` ніколи не містить
токена. Після відкликання або ротації токена виберіть у tray пункт «Оновити токен»; нове значення спочатку
перевіряється сервером і лише потім атомарно замінює credential.

Пункт «Змінити сервер / від’єднати» зупиняє worker, видаляє саме його credential і локальний `config.json`, після
чого знову відкриває майстер підключення. Серверний токен після цього все одно слід відкликати в адмін-панелі.

Перший запуск безпечно починається в режимі «Ніколи» і відразу відкриває налаштування графіка. Завантаження
моделі та claim почнуться лише після того, як користувач явно збереже інший режим.

Перед першим запитом на роботу клієнт завантажує та ініціалізує `large-v3`. Це може зайняти кілька хвилин і
кілька гігабайтів диска. Новий job не береться, поки модель не готова.
Початкове завантаження потребує вихідного HTTPS-доступу до Hugging Face. Для GPU потрібні актуальний драйвер
NVIDIA та сумісні CUDA/cuBLAS/cuDNN DLL у `PATH`; якщо їх бракує, клієнт автоматично спробує CPU, що суттєво
повільніше.

## Розклад

У налаштуваннях можна вибрати:

- **Цілодобово** — клієнт може виконувати транскрипцію в будь-який час;
- **Ніколи** — клієнт не робить claim і нічого не рахує;
- **За інтервалами** — один або кілька щоденних проміжків.

Початок інтервалу включний, кінець виключний. `10:00–16:00` працює з 10:00 до 15:59 включно.
`22:00–06:00` працює до й після півночі. Однакові початок і кінець заборонені; для повної доби існує окремий
режим.

Якщо дозволений час завершується під час Whisper, клієнт перериває роботу на найближчій межі сегмента,
звільняє lease і видаляє часткові файли. Якщо JSON уже сформований, зміна розкладу не скасовує його надсилання:
тимчасові мережеві помилки повторюються до п’яти разів із тим самим `submission_id`. Постійна відмова сервера,
втрата lease або вичерпання повторів завершує спробу без нескінченного утримання завдання.

## Локальні дані

Типові шляхи:

```text
%LOCALAPPDATA%\student-schedule-worker\config.json
%LOCALAPPDATA%\student-schedule-worker\Cache\models
%LOCALAPPDATA%\student-schedule-worker\Cache\jobs
%LOCALAPPDATA%\student-schedule-worker\Logs
```

Медіа зберігається лише на час активного job і видаляється best-effort після нього. Якщо живлення або процес
аварійно обірвалися, клієнт прибере осиротілі UUID job-директорії під час наступного запуску. Логи мають ротацію
і не повинні містити токенів, медіа чи транскриптів.

## Протокол сервера

Префікс API: `/community/v1`. Кожен запит використовує `Authorization: Bearer …`; job-запити додатково мають
`X-Transcription-Lease`.

```text
GET  /community/v1/me
POST /community/v1/jobs/claim
GET  /community/v1/jobs/{job_id}/media
POST /community/v1/jobs/{job_id}/heartbeat
PUT  /community/v1/jobs/{job_id}/result
POST /community/v1/jobs/{job_id}/release
```

Клієнт приймає для Whisper лише `audio/ogg`, не приймає redirect, абсолютний media URL або шлях за межами
`/community/v1` і не перейменовує `.part` до успішної SHA-256 перевірки. Серверний контракт і
приклад claim зафіксовані тестами в `tests/test_api_client.py`.

## Збірка Windows

`packaging/build.ps1` створює окреме build-середовище, запускає тести, збирає PyInstaller `onedir` і, якщо
встановлено Inno Setup 6, формує per-user інсталятор:

```powershell
.\packaging\build.ps1 -Python py
```

Модель не вбудовується в інсталятор. Перед публічною роздачею executable та installer потрібно підписати
сертифікатом code signing, щоб зменшити попередження Windows SmartScreen.

## Перевірки

```powershell
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m ruff check src tests
```

Тести використовують fake model, fake keyring і `httpx.MockTransport`, тому не завантажують Whisper, не
потребують GPU та не запускають GUI.
